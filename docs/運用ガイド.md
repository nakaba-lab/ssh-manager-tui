# 運用ガイド（sshm）

運用者・上級ユーザー向け。`sshm` はローカルで動く単一バイナリ（サーバ・常駐サービスは無い）ため、運用は**ローカル状態ファイルのバックアップ／復旧**と**アップグレード**が中心。運用規律の一般則は [`.claude/rules/operations.md`](../.claude/rules/operations.md)。

> **公開注意**: `docs/` は Pages に自動公開される。接続先・内部手順・鍵/秘密は本書に書かず、保管場所への参照に留める。

## ローカル状態ファイル（すべて `~/.ssh/` 配下・owner-private）

| ファイル | 内容 | 秘密 |
|---------|------|:---:|
| `config` | SSH 設定（真実源） | — |
| `sshm-vault.json` | 暗号化された秘密（パスワード・パスフレーズ） | 暗号化済み |
| `sshm-prefs.json` | 非秘密設定（オートフィル opt-in 等） | — |
| `sshm-history.json` | 接続履歴（alias→最終接続時刻） | — |

## バックアップ・復旧

- **バックアップ**: `~/.ssh/` 配下の上表 4 ファイルを、本番と障害を共有しない別系統（別ディスク・別ホスト）へ定期コピーする。`config` は保存のたびに `config.bak`（セッション初回）も作られる。
- **復旧（リストア演習）**: 退避したファイルを `~/.ssh/` に戻す。**vault は復元後にマスターパスワードで開けることを実際に確認する**（「取れている」ではなく「戻せる・開ける」ことを確かめる）。復旧手順が現状で通用するかを定期的に演習し、この節に実測を記録する。
- **vault のマスターパスワード**を失うと保管庫は復号できない（設計上、永続化されない）。マスターパスワードはパスワードマネージャ等で安全に保管する。

## アップグレード

- crates.io: `cargo install sshm-tui --force` ／ Scoop: `scoop update sshm-tui` ／ winget: `winget upgrade NakabaLab.sshm`。
- アップグレード後も `~/.ssh/` の状態ファイルはそのまま使える（後方互換のファイル形式）。

## 障害時の初動

- 保存で異常があっても `config.bak`（初回保存時のバックアップ）から手動で戻せる。
- 本番影響を伴う不具合は incident として起票し、`.claude/rules/operations.md` の障害対応フローに乗せる。
